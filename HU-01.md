# HU-01 — Definir y probar el login con token sin usuario

## Origen
- Componente: web.
- H-WEB-03 — Cobertura de pruebas del flujo de login y dashboard incompleta.
- Evidencia: `web/src/app/session/session-flow.spec.ts:35,92,112`; `web/src/app/utils/legacy-format.spec.ts:4,5,6`.
- Contexto adicional del hallazgo: `web/src/app/session/session-flow.spec.ts:40,104,124,139,155,171,189,199,216,229,241`.

## Contexto
- La matriz registra que hay pruebas para distintos estados de login y dashboard, pero el resultado de login con token y sin `user` no está definido por el contrato.
- El hallazgo permanece pendiente por esa definición faltante. Esta HU no presupone si el resultado debe ser éxito o error.

## Ajustes necesarios
- Acordar y documentar el resultado esperado cuando la respuesta de login contiene un token, pero no contiene `user`.
- Agregar una prueba de caracterización del flujo web que compruebe el resultado acordado.
- Mantener cubiertos los casos existentes del flujo de login y dashboard; no alterar el comportamiento de otros escenarios como parte de esta HU.

## Criterios de aceptación
- El contrato documenta el comportamiento esperado para una respuesta de login con token y sin `user`.
- Una prueba automatizada reproduce esa respuesta y verifica el resultado acordado, incluyendo el estado de sesión y la navegación que correspondan al contrato.
- Las pruebas existentes del flujo de login y dashboard continúan pasando sin cambios en su comportamiento observado.

## Evidencia esperada
- Actualización del contrato o documentación que registre la decisión sobre token sin `user`.
- Prueba automatizada del escenario y salida del comando de pruebas web ejecutado.
- Evidencia identificada como componente web, hallazgo H-WEB-03.
